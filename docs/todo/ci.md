# CI

- **Seen once: CI's job `browser` hung in four packages at once.** On 2026-11-19, on pull request #63, the tests of `internal/sqlite`, `internal/sqlite/faultvfs`, `internal/core`, and `internal/sim` ran until the timeout of 30 minutes ("the program did not exit within a minute after its -test.timeout"), while the three packages after them passed. A rerun passed. The pull request did not change those packages. It was not looked into. If it comes again, the hang should give a stack, and the timeout of the job should be far shorter than 30 minutes.
- **The check of the simulator's page hangs at times, and the hang is not fixed.** CI's job `site` hung in 7 of 132 runs from 2026-11-18 to 2026-11-20, first on pull request #70: `make site-check` printed "sitecheck: the check did not end within 10m0s" and nothing else, where a check that ends takes 34 s at the median and 63 s at the most, and a rerun passed. Since pull request "Make CI faster and more reliable", the check stops after 3 minutes, and then prints the stacks of its goroutines, the requests of the page so far, and the output of Chromium. It does not print the page's console or its state: Chromium writes the console to its output only with `--enable-logging=stderr`, and the state needs `check.html` to report it, both in `internal/simulator`, which another piece of work owns. The cause is not known.
- **The planted-bug tests stop a bug's subtest at its first seed with an unknown symptom, which can hide a later seed of the same bug in the nightly.** `TestSimulation_plantedBugs` of `internal/core` (`is.True(t, known, …)`) and of `internal/engine` (`t.Fatalf("seed %v finds the bug by another violation …")`) end the subtest of a bug at the first seed whose violations hold none of its symptoms. CI stops at the first few seeds that find the bug anyway, so this matters only for the nightly's 1000 seeds, where a second unknown symptom of the same bug shows only the night after the first is accepted. `TestDifferential` had the same effect, which hid sequence 25196 behind 16832 from 2026-11-21 to 2026-11-25 (issue #117); it now reports up to ten failing sequences. The planted-bug tests could report each such seed with `t.Errorf` and go on, in a few lines each; it was left for now, since the engine's tests were being changed on another branch at the time.
