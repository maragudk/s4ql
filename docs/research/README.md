# Research notes

These are raw research notes gathered on 2026-11-10 while planning the project. AI research agents wrote them from the cited sources. The notes tag claims as verified or inferred. They are a snapshot and are not kept up to date.

The distilled ideas are in [../inspiration.md](../inspiration.md). Agreed decisions are in [../spec.md](../spec.md).

- [object-storage-architectures.md](object-storage-architectures.md): survey of turbopuffer, SlateDB, Delta Lake and Iceberg, plus S3 and Tigris semantics.
- [testing-strategies.md](testing-strategies.md): testing techniques and Go tooling.
- [external-test-suites.md](external-test-suites.md): external SQL correctness suites, benchmarks, and a Postgres wire adapter.
- [s3-fault-injection.md](s3-fault-injection.md): tools for injecting faults into S3.
- [slatedb.md](slatedb.md): notes on SlateDB.
- [graft.md](graft.md): notes on Graft.
- [foundationdb.md](foundationdb.md): notes on FoundationDB.
- [litestream-vfs.md](litestream-vfs.md): notes on Litestream, LTX, and the Litestream VFS.
- [tigris-probe-results.md](tigris-probe-results.md): measured behaviour of a real Tigris bucket.
- [sqlite-cache-and-oracle.md](sqlite-cache-and-oracle.md): design space for SQLite as local cache and as test oracle, change-capture mechanisms, Go bindings, and prior art.
- [sqlite-best-practices.md](sqlite-best-practices.md): best practice for SQLite in server-side apps, the legacy behaviours to reject or match, the costs of STRICT plus WITHOUT ROWID, and migration practice.
- [sqlite-docs-inventory.md](sqlite-docs-inventory.md): inventory of the SQLite 3.54.1 SQL documentation (features, legacy flags, STRICT and WITHOUT ROWID rules, oracle configuration, a proposed slice ladder, and hard semantic areas).
- [commit-acknowledgement.md](commit-acknowledgement.md): what comparable systems tell the client, and what the node does, when a commit is durable in the authoritative place and the local apply then fails.
- [sqlite-compile-options.md](sqlite-compile-options.md): every SQLite 3.54.1 compile-time option on compile.html, classified for the build in `internal/sqlite`, with the ten options agreed.
- [sqlite-busy.md](sqlite-busy.md): why a single writer gets `SQLITE_BUSY` among readers in WAL mode, the other ways a lock wait reaches us, the options including the `unix-excl` VFS, and a classification of SQLite's result codes.
- [change-file-encodings.md](change-file-encodings.md): binary encodings for the change file (Protocol Buffers with and without generated code, CBOR, SQLite's changeset, FlatBuffers, Cap'n Proto, Avro, and others), what comparable systems use for their logs, and a ranked shortlist with a layout sketch.
- [change-file-contents.md](change-file-contents.md): how PostgreSQL, MySQL, the SQLite session extension, Delta Lake, Debezium, Spanner, CockroachDB, Dolt, and SQLite replication systems represent row changes, schema changes, statements, and unknown record kinds in their logs, with recommendations for what s4ql's change file holds.
- [protobuf-practices.md](protobuf-practices.md): Protocol Buffers best practice for the commit object (schema evolution, `oneof`, `proto3` or editions, presence, enums, naming, well-known types, streaming, the Go API, Buf lint and breaking checks, decoder options), with a review of the draft schema and a revised `.proto` file.
- [s3-clock.md](s3-clock.md): whether the object store can be the lease's clock (`Date` against the manifest's `Last-Modified`), what AWS S3, Tigris, MinIO, R2, GCS, B2, and Garage do with those two timestamps, a test against Tigris, prior art for leases on object stores, the clock-free rule of Kubernetes and the DynamoDB Lock Client, and a failure analysis.
- [sql-front-end.md](sql-front-end.md): how to build the first SQL slice: SQLite's tokenizer and how to check a Go copy against it, parser options in Go (including a port of `parse.y`), SQLite's exact errors for slice 1 as measured on 3.54.1, how SQLite-compatible engines test against their reference, the `database/sql` driver contract and its retry hazard, and the layers of the engine over `internal/core`.
- [rqlite-sql.md](rqlite-sql.md): whether `github.com/rqlite/sql` can be s4ql's SQL parser, measured against SQLite 3.54.1 on 68,032 statements: acceptance in both directions, its tokenizer, its errors and their positions, what its syntax tree keeps and loses, fuzzing, the options for using it, and bugs that could be reported upstream.
- [meyer.md](meyer.md): `sqlc-dev/meyer` as s4ql's SQL parser, measured against SQLite 3.54.1 through the binding on 535,220 statements, with `rqlite/sql` on the same inputs: acceptance, error messages and offsets, tokens, the syntax tree and a check of its shape by evaluation, robustness, the project's state, and the options with a comparison table.
- [sqlite-parse-tree.md](sqlite-parse-tree.md): whether s4ql can read SQLite 3.54.1's parse tree out of its memory: SQLite's debug tree printer, a walker of our own over a parse in the rename mode of `ALTER TABLE`, the schema after a statement ran, and Lemon's parser trace, each run and shown; what the grammar's actions have already lowered; what a tree comparison could and could not assert; coverage by statement kind; build and version questions; and the costs in trust.
- [sqlite-in-the-browser.md](sqlite-in-the-browser.md): how `internal/core` can run in a web browser with SQLite: the official SQLite WebAssembly build bridged from Go by JavaScript, `ncruces/go-sqlite3` (now translated to Go by wasm2go, and its older wazero form), `modernc.org/sqlite`, and other routes, with the real core and its tests run in Chromium on two of them, timings, sizes, trace hashes against native, and a ranking by faithfulness.
- [feature-map.md](feature-map.md): a map of SQL features by area as of 2026-11-24: what s4ql supports, what it lacks, what glue still needs, and the core gaps that most missing features wait on, each with the decision it needs.
- [memory-bounds.md](memory-bounds.md): what bounds the memory of operators that hold rows (sort, grouping, joins, distinct, RETURNING) in SQLite, PostgreSQL, MySQL, DuckDB, CockroachDB, TiDB, Go and embedded engines, and hosted SQLite, what happens at the bound, how the designs changed over time, and what s4ql has today for a spool or a limit.
- [non-determinism.md](non-determinism.md): every input other than a statement's text, parameters, and committed state that decides what it returns or writes or whether it fails, from SQLite 3.54.1's source, its documentation, and measurements, with the built-in functions not flagged deterministic and s4ql's own kinds.
- [adversarial-core-2026-11-26.md](adversarial-core-2026-11-26.md): an adversarial review of `internal/core`, `internal/store`, and `internal/format` by codex and agy, each claim checked against the code: four confirmed faults with failing tests (two identical commit objects both acknowledged, a takeover on a shared cache that stops the new holder, a reader on a cache file that replaced the holder's, an overflow of the wait for a lease), and why the other claims do not hold or do not matter.
